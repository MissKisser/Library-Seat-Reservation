# 跨天预约修复计划 — 14:00 批量"约错到当天"根因修复

> 创建：2026-08-26（上午）
> 状态：**已实施并实弹验证通过**（2026-08-26 下午；终版通道 = 页面内改写 + enc 重算；08-27 六段已全部补约核验）
> 前置事实：2026-08-25 14:00 事故已定位根因但未修复；本计划是当时承诺的"今天内完成，明天不裸奔"的正式交付物

---

## 1. 问题陈述（业务语言）

系统的核心动作是"每天 14:00 抢明天的 6 个守护时段"。但实际发生的是：

- **抢到的全是"今天"的时段**——昨天 14:00 给 08-26 生成的 6 条任务里，15-17 / 19-21 四条约到的是**昨天当天**的下午和晚上（事后被 task16-19 接管并签退），今早 9-11 两条因当时格子已过时点击失败；
- **今天 08-26 的 15-21 点实际毫无真实保护**——库里 4 条"进行中"任务挂的全是昨天已作废的旧预约号（幻影任务）；
- 若不处置，**今天 14:00:10 会原样重演**：给 08-27 生成的任务又约到 08-26 当天。

## 2. 根因（两条，均已实测证实）

| # | 根因 | 证据 |
|---|---|---|
| R1 | **超星座位页无视日期参数**：`/front/apps/seat/code?...&day=明天` 打开的永远是**今天**的格子，页面上不存在任何日期切换控件 | 08-25 用 debug_seat_page.py 只读实测：改 day 参数页面渲染不变 |
| R2 | **选格点击静默失效**：14:00 抢位高峰时部分格子未开放（noSelect 样式），点击被页面吞掉且无任何报错，程序误以为已选中 → 只约到"尾巴"格子 | 08-25 事故中仅尾部时段成功；记忆档案 chaoxing-seat-code-page-behavior 亦有记录 |

注意：R1 是"约错日子"的根因；R2 是"只约到部分时段"的根因。两条都要修。

## 3. 修复目标与验收标准

**目标**：14:00 批量预约能真正约到**次日**的指定时段。

**验收标准（全部满足才算修复完成）**：
1. 用 xiongjt 实弹预约 **08-27** 104 座一个 30 分钟小时段成功，且：
   - 服务端可查（`/reservelist` 出现该预约，日期=08-27）；
   - 占用查询（`/getusedtimes` day=08-27）显示该时段被占；
2. 预约后立即取消（cancel 支持未开始时段），确认 08-27 该时段释放；
3. 14:00 批量为 08-27 生成 6 条任务全部拿到**属于 08-27 的预约号**，且 08-26 当天不再产生任何误约；
4. 失败安全：新通道失败时任务标 FAILED 并告警，**绝不静默回退到"约当天"**。

## 4. 方案设计

### 4.1 通道 A（主通道）：页面取令牌 + 直连提交指定日期

**思路**：预约页虽然只显示今天，但**预约接口本身接受 day 参数**（07-09 研究文档 docs/superpowers/specs/2026-07-09-chaoxing-api-reference.md 已证实）。缺的只是防伪令牌 `enc`——它是浏览器会话绑定的，必须在真实页面里生成。

**流程**（Playwright + httpx 两段式）：

```
1. 复用 scheduler 账号 cookie 打开"今天"的座位页（新开页面,不碰已有会话）
2. 注册请求拦截: page.route("**/data/apps/seat/submit", → abort)
   —— 关键: 让页面的提交请求"出发即被掐断",绝不会约到今天
3. 像现在一样点选格子 + 点"开始使用"
   → 页面 JS 构造完整请求体(含新鲜 enc/wyToken)
   → 我们从被拦截的请求体里 harvest enc/wyToken
   → 请求被 abort,今天不产生任何预约
4. 用 httpx 直连 POST /data/apps/seat/submit,
   参数 = 被拦截请求体的原样字段, 仅改两处:
     day    = 目标日期(明天)
     startTime/endTime = 目标时段
5. 解析返回, 拿到预约号
```

**代码落点**：
- `seatbot/client.py`：新增 `harvest_enc_via_page()`（上述 1-3 步）+ 重新引入 `submit_reserve()`（直连 POST，即 08-26 审查时删除的 #14 壳，当时已注明"跨天修复落地时按需重写"）
- `seatbot/scheduler.py` `_run_submit`：任务日期 > 今天 → 走通道 A；== 今天 → 走现有浏览器通道（当天场景页面即真相）

### 4.2 通道 B（兜底加固）：选格校验，只救当天预约

对现有 `submit_in_browser` 补两道校验（修 R2）：

1. **逐格验证选中态**：每点一格后检查该格 class/样式变化（选中态样式），未选中则重试（最多 3 次，间隔 500ms）；
2. **提交前总校验**：点"开始使用"前，核对页面当前选区文本与请求时段完全一致，不一致直接报错退出——**宁可失败，不可约偏**。

通道 B 依然只能约当天（受 R1 限制），定位降级为：当天补位 / quick-reserve / 应急。

### 4.3 事后核验（不信提交回执，信服务端状态）

批量提交后，对每条成功任务追加核验：`get_used_times(seat, day=目标日)` 应包含该时段。核验失败 → 任务标 FAILED + ERROR 日志，进入人工视野。

## 8. 风险与回滚

| 风险 | 概率 | 缓解 |

| 拦截方案让页面报错干扰 harvest | 低 | abort 发生在 harvest 之后，页面状态不再使用 |
| 回滚 | — | 新通道完全失败时：`_run_submit` 回退仅当天模式（现状），未来日期任务一律 FAILED 不误约；代码用开关 `runtime.direct_submit_enabled: true/false` 控制，一改配置即回滚 |
